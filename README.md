# لوحة هوتيلنا

لوحة صاحب نظام هوتيلنا لإدارة الفنادق التي اشترت النظام. منفصلة عن النظام نفسه، ولصاحبه فقط.

## ما فيها

- **الفنادق**: الأقسام المشتراة لكل فندق، وحالته (فعّال أو موقوف)، وآخر تواصل لنظامه ونسخته.
- **كود الربط**: يُكتب في نظام الفندق أول مرة يفتح، مرة واحدة، فيرتبط النظام باللوحة.
- **مفتاح يدوي**: لنسخة التثبيت على جهاز بلا إنترنت، مربوط ببصمة الجهاز.
- **الإشعارات**: لكل الفنادق أو لفنادق محددة، عادية أو مهمة، بمدة اختيارية.

## كيف يتصل نظام الفندق باللوحة

1. `POST /api/v1/activate` بكود الربط: يعيد معرّف النظام وسرًّا مشتركًا وترخيصًا موقّعًا.
2. `POST /api/v1/checkin` دوريًا، موقّعًا بالسر المشترك (HMAC على الوقت والمحتوى): يعيد الترخيص الحالي والإشعارات السارية.
3. الترخيص موقّع بمفتاح Ed25519 الخاص باللوحة. نظام الفندق يحمل المفتاح العام فقط (`/api/v1/public-key` وصفحة الإعدادات)، فيتحقق ولا يستطيع الإصدار.

البيع دائم والتحديثات مجانية للأبد، فلا تاريخ انتهاء للترخيص. الإيقاف يصل للنظام المتصل في أول تواصل.

## التشغيل

- على Netlify: البيانات والمفاتيح في مخزن Netlify Blobs الخاص بالموقع. المتغير الوحيد المطلوب `ADMIN_SETUP_CODE` لإنشاء كلمة المرور أول مرة، ولا يُقبل بعدها.
- محليًا: `bun install` ثم `bun run dev`. البيانات في مجلد `.data`، ويمكن تشغيل الخادم بـ `LOCAL_HTTP=1` على http.

## الاختبار

`bun run test` و `bun run lint` و `bun run typecheck`.
